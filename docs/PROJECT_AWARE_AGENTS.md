# Project-aware AGENTS.md

Starting with Web Development Agent Kit `v1.1.2`, installation discovers the target web project before finalizing its agent instructions.

## What installation discovers

The installer creates a lightweight structural profile containing:

- project name;
- project directory name;
- detected technology groups and skills;
- shallow project structure;
- important manifests/build files;
- important configuration files;
- test roots;
- migration/data-change roots.

Source file contents are **not** embedded into the profile.

## Generated AGENTS.md layout

A newly installed project receives an `AGENTS.md` shaped like this:

```text
Project Agent Context — <project name>
├── Project Identity
├── Detected Technology Stack
├── Shallow Project Structure
├── Important Manifests / Build Files
├── Important Configuration Files
├── Test Roots
├── Migration / Data Roots
└── Project-aware Routing Rules

Web Development Agent Kit
├── Canonical Workflow
├── Context / Token Rules
├── Maintainability Contract
├── Web Agent Team
├── DevOps Agent Team
└── Skill Policy
```

The project context appears **before** the generic Web Kit roles so the Captain can understand where it is working before choosing agents and skills.

## Machine-readable project profile

The same generated context is stored at:

```text
.agent-core/index/project-profile.json
```

The Context Router can use this profile without rereading `AGENTS.md` or scanning the repository from scratch.

## Example

For a project containing React + TypeScript + ASP.NET Core + PostgreSQL + Docker, the generated header can look like:

```markdown
# Project Agent Context — game-hub

## Project Identity
- Project name: `game-hub`
- Development domain: Web Development

## Detected Technology Stack
- Languages: `typescript`, `csharp`
- Frontend: `react`
- Backend: `aspnet-core`
- Data / ORM: `postgresql`, `entity-framework-core`
- DevOps / Delivery: `docker`

## Project Structure — Shallow Routing Map

frontend/
frontend/src/
backend/
backend/Controllers/
backend/Services/
tests/
docker-compose.yml
```

This map is routing metadata only. It does **not** authorize an agent to read all of those directories.

## Existing AGENTS.md

The installer avoids destroying user-owned instructions.

- If no `AGENTS.md` exists, the kit creates a project-aware `AGENTS.md`.
- If `AGENTS.md` was previously generated by this kit, update/install refreshes it automatically.
- If an unrelated user-owned `AGENTS.md` already exists, the kit preserves it and writes the generated Web Kit instructions to `AGENTS.web-kit.md`.
- `--force-agents` explicitly allows replacement of the root `AGENTS.md`.

## Refreshing after project changes

Running the Web Kit update/install flow regenerates the project profile, so newly added frameworks, test roots, infrastructure, or major structure changes can be reflected in the generated context.
